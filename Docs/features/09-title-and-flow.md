# タイトル画面とゲームの流れ

## 目的

起動 → タイトル → プレイ → 結果 → リトライ／タイトルへ、の 1 周を通す。05 では「シーンを開くとすぐ開始、結果からはリトライだけ」だったのを広げる。

## 仕様

- 起動するとタイトル画面（`Title` シーン）を出す
  - タイトル文字は TextMeshPro のテキスト（仮の名前）。ゲーム名が決まったらシーン上のテキストを書き換えるだけで差し替えられる
  - ロゴ画像は使わない
- タイトルでクリックか何かのキーを押すと `Game` シーンを読み込んでプレイが始まる
- ゲームオーバーの結果画面に「RETRY」「TITLE」の 2 つのボタンを出す
  - キーでも選べる: R ＝ リトライ、T ＝ タイトルへ
  - リトライは `Game` シーンを読み込み直してすぐ次のプレイを始める（タイトルは挟まない）
- クリアの結果画面は「TITLE」ボタンだけ（T キーでも可）。リトライはない

## 決定事項

- タイトルは Game と別のシーンにする（11/13）
  - 理由: このあとレベル選択を作る予定で、タイトル側に画面が増えるため。同じシーンに重ねる案より、タイトル側の作業を Game に影響させずに進められる
- 結果画面の選択はボタンとキーの両方（11/13）。マウスだけでもキーボードだけでも遊べるように
- クリア時はタイトルへ戻るだけにする（11/13、ユーザーの判断）
- 05 の「結果画面でどこをクリックしてもリトライ」はやめる。ボタン以外のクリックは何もしない（押し間違いでタイトルに戻ったりリトライしたりしないように）
- 結果を出してから 0.3 秒は選択を受け付けない（05 から引き継ぎ）

## 実装メモ

- 変更: `TitleScreen`（Title シーンの Systems の子）が入力を待って Game を読み込む。`GameManager` に `Retry` / `GoToTitle` を足し、結果画面のボタン（On Click）と R / T キーの両方から呼ぶ。`GameUI` はゲームオーバーのときだけ RETRY ボタンを出す
- 設計判断: リトライの可否（ゲームオーバーのみ）は `GameManager.Retry` 側でも確かめる。ボタンを隠すだけだと R キーでクリア後にリトライできてしまうため
- 設計判断: 入力を待つ時間の名前を `choiceInputDelay` に変えた。`[FormerlySerializedAs]` でシーンの値を引き継いでいる
- 注意点: 結果画面は `Time.timeScale = 0` のままシーンを移るので、`TitleScreen.Awake` で 1 に戻している（Game 側は `GameManager.Awake`）。シーンを増やすときも、どこかで戻すこと
- 注意点: 起動時のシーンは Build Profiles の Scene List の 0 番（Title）。シーンは名前で読み込む（`gameSceneName` / `titleSceneName`）ので、名前を変えたらインスペクターも直す
- 注意点: ボタンは `ResultPanel/Buttons`（Horizontal Layout Group）に入れて、RETRY を隠しても TITLE が中央に寄るようにしている。子の合計幅が親の幅を超えると中央寄せが効かず左端から並ぶので、`Buttons` の Width は 2 つ並べても収まる幅にしておく
- 動作確認: エディタで Title から Play し、開始、ゲームオーバー後の RETRY / TITLE（ボタンとキー）、クリア時は TITLE だけ出ることをユーザーが確認した（11/13）。WebGL ビルドは未確認
