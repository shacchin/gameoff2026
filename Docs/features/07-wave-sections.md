# 波の生成制御（セクション制）

## 目的

現行のポータル形式のまま、「危機をテンポよく捌くフロー感」を作れるか検証する（ブランチ `proto2-wave-feedback`）。
難しさを車の台数ではなく「事故が起きるタイミングの同時性と間隔」で付け、山と谷のある 60 秒にする。

## 仕様

- 60 秒を 20 秒 × 3 セクションに分け、セクションごとに数値を持つ
  - 第 1 幕（0–20s）導入: 事故は単発、間隔は広め
  - 第 2 幕（20–40s）展開: 同時に 2 件・短い間隔で続く事故（連鎖）を混ぜる
  - 第 3 幕（40–60s）クライマックス: 事故の密度がピーク
- 各セクションに「山場」の時間帯を決め、その間は事故の間隔を詰める（08 で背景の彩度も上げる）
- 各セクションの終わりの数秒は「谷」: 事故を起こさず、車の出現もゆっくりにする
- 警告→事故の秒数、シフト時間、車の速度、セクションごとの数値は `GameTuning`（ScriptableObject）1 つにまとめる

## 決定事項

- 事故は「予約」して起こす（11/8）
  - 交差する 2 経路を選び、決めた時刻にちょうど交差点で出会うよう、出す時刻を逆算して 2 台を出す
  - それ以外の車（つなぎの車）は、ほかのどの車ともぶつからない経路にだけ出す。予約済みでまだ出ていない車、別次元から戻る車も含めて調べる
  - 理由: ランダムに出すと事故がいつ起きるかが偶然になり、同時性・間隔・谷を保証できない
  - プレイヤーがずらした車が起こす事故は防がない（04 の「解決した結果が次の問題を生む」はそのまま残す）
- 「連鎖」は、別の交差点で短い間隔（0.7〜0.8 秒）で続けて起きる事故とする（11/8）。捌いた結果が次を生むよう仕込む案は見送り
- 山場は、セクションの中の決まった時間帯にする（11/8）。その場の事故の数からは決めない
- 数値の置き場は ScriptableObject `GameTuning`（11/8）。再生中に変えた値も残るので、遊びながら調整できる
- 予約に使う交差点は、2 台とも出てから交差点まで warningTime 秒以上かかるものだけにする（11/8）
  - 理由: まだ出ていない車は予告できないので、出現点に近い交差点を使うと予告が短くなる。今のマップでは、縦の経路で出現点に近いほうの交差点が外れる

## 実装メモ

- 変更: `WaveDirector`（Systems）が経過時間とセクションを持ち、`SectionStarted` で知らせる。`CarSpawner` は事故の予約（`UpdateAccidents`）とつなぎの車（`UpdateFiller`）を受け持ち、時刻はすべて `WaveDirector.Elapsed` 基準
- 設計判断: 車は「いつから・どこから走るか」（`CarSpawner.Track`）で表し、今いる車・予約済みの車・別次元から戻る車を同じ形で未来の位置まで調べる（`IsSafe`）。戻る時刻を知るため `Car.ShiftOut` に秒数を渡すようにした
- 設計判断: 予約に失敗したら事故の時刻を少し遅らせて試し直す。谷に入ったら次のセクションの最初の事故にずらす（`NormalizeAccidentTime`）
- 設計判断: 出す予定の時刻からフレームの分だけ遅れたぶんは `Car.Init` の開始距離で取り戻す（予約した事故の時刻がずれないように）
- 注意点: `WaveDirector` は `DefaultExecutionOrder(-100)` でほかより先に時間を進める。外すと CarSpawner と 1 フレームずれる
- 注意点: `GameTuning` は WaveDirector・AccidentPredictor・PortalPlacer の 3 か所に割り当てる（CarSpawner は WaveDirector 経由）。外れていると LogError を出してそのコンポーネントを止める
- 注意点: Car Speed や Warning Time を上げると使える交差点が減る。起動時の「事故に使える交差点: N 個」で確かめる
- 注意点: 安全確認は失敗すると最大で交差点の数 × 2 台ぶん未来の位置をなめる。重ければ `step` を広げる（WebGL では未計測）
- 動作確認: エディタで Play し、予約どおりに事故と予告が出ることをユーザーが概ね確認した（11/8）。数値の調整と WebGL ビルドは未確認
