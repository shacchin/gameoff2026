# 事故でスコアを稼ぐ（ルール転換）

## 目的

コアルールを「事故を防ぐ」から「事故を起こしてスコアを稼ぐ」に変える。ポータルで車のタイミングをずらし、狙って事故を起こす遊びにする。

## 仕様

> 11/22 に「60 秒で終わり」をやめ、時間無制限＋警察車両を 3 台見逃したらゲームオーバーにした（13）。スコアの仕組みはこのファイルのまま。

- 事故が起きてもゲームは止めない。60 秒たったら終わり、リザルトへ進む（ゲームオーバーはなくなる）
- 事故 1 件ごとにスコアを固定点（初期値 100、`[SerializeField]`）加える
  - プレイ中は画面に今のスコアを出し続ける
- 事故の瞬間のフィードバック
  - 事故の地点に事故マークを出す（今のゲームオーバー時のマークを流用）。少しのあいだ見せてから消す
  - 事故の地点に「+100」のポップアップを出す（上に浮かびながら消える）
- 事故に関わった車は、事故の瞬間にすぐシーンから消す（交通の流れを止めない）
  - 玉突き・連鎖・事故車を残す仕様は入れない
- 事故予告（「！」マークと車の点滅）は出さない（コードは残し、設定でオフにする）
- リザルトは「時間終了による結果」として、最終スコアを出す
  - ボタンは常に RETRY と TITLE の両方を出す（キーも R ＝ リトライ、T ＝ タイトルへ）

### 今回やらないこと

- タンクローリー・爆発
- 玉突き・コンボなどのボーナス（スコアは事故 1 件 ＝ 固定点のみ）
- 交通の出現パターンの調整（今のまま。自然に起きる事故もスコアに入れる）
- ポータルの仕様変更（最大 3 個・2 秒で帰還・1 台で消費はそのまま）→ 帰還までの秒数だけ、遊んだあとに 1 秒へ変えた（決定事項）
- ゲーム名・タイトル画面の変更

### 進め方

1. ルールの転換: 事故で止めない／事故車を消す／スコアを数えて表示／60 秒でリザルト（最終スコア）
2. 事故のフィードバック: 事故マークを一定時間で消す／「+100」のポップアップ
3. ドキュメント: 05 と CLAUDE.md の企画欄を新ルールに書き換え、実装メモを書く

## 決定事項

- 事故を起こした車は、止めて見せずにすぐ消す（11/16、ユーザーの判断）
  - 事故の瞬間に判定から外すので、ほかの車がぶつかって連鎖することはない
- 1 台が数える事故は 1 件だけ。3 台が同時に重なったら、2 台で 1 件、残りの 1 台はほかの車との組で調べる（11/16）
- 事故予告（「！」と点滅）は出さない（11/16、ユーザーの判断）。コードは残し、`AccidentPredictor` の `showWarning` で切り替える
  - オフのときは「今ぶつかっているか」だけを調べる（未来の位置を計算しない）
- 結果画面は RETRY と TITLE を常に両方出す（11/16、ユーザーの判断）。ゲームオーバーがなくなり、RETRY を出す場面がなくなるため
- 「+100」は描画順 220（マーク帯域、事故予告の「！」より手前）
- 事故の予約（07）は減らして残す（11/16、ユーザーの判断）。`GameTuning` の数値だけで調整し、コードは変えていない
  - 理由: 予約した事故はプレイヤーが何もしなくても起きて点になる（60 秒で 20 件前後）。ポータルを使う意味が薄れるので、放っておいて起きるのは 1 幕 2 件くらい（60 秒で 6〜7 件）の「おまけ」にする
  - 事故の間隔を 1 幕から順に 8〜10 / 7〜9 / 6〜8 秒に広げ、山場も同じ間隔にした（山場の時間帯と背景の彩度は残す）。同時・連鎖は 0
  - 事故 1 件で 2 台出ていたぶん車が 3 分の 1 ほど減るので、つなぎの車の間隔を 1.0 / 0.75 / 0.55 秒に詰めて補った。つなぎの車はそれだけではぶつからないので、プレイヤーがぶつける相手だけが増える
  - 遊んで決めた値ではない。何もしないときと狙ったときのスコアの差、第 3 幕の混み具合はまだ確かめていない
- ワープの時間（`GameTuning.shiftDuration`）を 2 秒から 1 秒にした（11/16、ユーザーが遊んで調整）
  - 理由: 2 秒だと長すぎて、ほかの車とぶつかるタイミングに合わせにくかった
  - 戻ってくるゴーストは「シフト時間 × 車の速度」だけ手前から走ってくるので、出てくる距離も半分になる
- つなぎの車は、縦と横の道路のうち、いま車が少ないほうに出す（11/16、ユーザーの判断で「画面に見える台数」をそろえる）
  - 理由: 横の道路（32 マス）は縦（19 マス）より長く、車が画面にいる時間が約 1.8 倍ある。経路を同じ確率で選ぶと、横ばかりに車が見えた
  - 経路の長さに反比例して選ぶ方法は効かなかった。縦の車は、車の多い横の道路を横切るので「ぶつからないか」の確認で落ちやすく、落ちると横に回ってさらに横が増えた（横 5.7 台 / 縦 2.6 台）
  - 少ないほうに出せないときは、もう一方には回さず少し待つ。直したあとは横 4.6 台 / 縦 4.2 台（走っている台数の平均、ユーザーが計測）
  - 確かめるときは `CarSpawner` の `Log Schedule` をオンにすると、終わったときに縦と横の台数が Console に出る
- つなぎの車の間隔を 0.65 / 0.55 / 0.55 秒にした（11/16、ユーザーが遊んで調整）。縦と横をそろえて画面の車が減ったぶんを増やした
- 背景（地面の Tilemap）の赤さを、セクションと山場ではなくスコアで決める（11/16、ユーザーの判断）。`BackgroundTint` が `GameManager.Score` に比例して彩度を上げる
  - 理由: 新しいルールでは、プレイヤーが稼いだ点の伸びを見せたほうが手応えになる。時間で赤くすると、何もしなくても赤くなる
  - 一番赤くなる点数（`scoreForMaxRed`）は、ユーザーが遊んで 2000 点にした
  - → 11/28 に、最後の幕に入るスコア（`GameTuning` の最後のセクションの `scoreToEnter`、いまは 3000 点）で一番赤くなるようにした。幕の数値を変えると背景も合う（ユーザーの判断）。`scoreForMaxRed` は消し、`BackgroundTint` に `GameTuning` を設定する
  - 山場の時間帯は、事故の予約の間隔を変える役割だけが残る（いまは山場も通常と同じ間隔なので、効いていない）

## 実装メモ

- 変更: `AccidentPredictor` が終わるまで事故を調べ続け、事故の 2 台を `Car.Crash` で消す。`GameManager` が `Score` を持ち、事故マーク（一定時間で破棄）と `ScorePopup` を出す。`GameUI` はスコアと最終スコアを表示するだけ
- 設計判断: 消すのは全部の組を調べ終わってから（`crashed` 配列で印を付ける）。`Crash` は `SetActive(false)` してから `Destroy` し、同じフレームのうちに `Car.All` から外す
- 設計判断: `ScorePopup` にはスクリプトを付けず、文字（`+点数`）と動きは `GameManager.ShowScorePopup` が付ける。薄くするのは `DOTween.To` で `TMP_Text.alpha` を動かす（DOTween の TextMeshPro 用モジュールに頼らない）
- 設計判断: `GameManager.State` は残して値を `Playing` / `Finished` にした。`GameEnded` を購読している側（CarSpawner など）の引数を変えずに済むため
- 注意点: `ScorePopup` の `Visual` は 3D Object の TextMeshPro。UI 版にすると Canvas の外では表示されない
- 注意点: 事故マークとポップアップは timeScale に従うので、60 秒で止まった瞬間に出ていたものは結果画面の後ろに止まったまま残る
- 注意点: 予告を戻すなら `showWarning` をオンにする（`GameTuning.warningTime` を使う）
- 動作確認: エディタで Play し、事故で車が消えてスコアが加わる、ゲームが止まらない、60 秒で最終スコアと RETRY / TITLE が出る、「+100」が浮かんで消えることをユーザーが確認した（11/16）。WebGL ビルドは未確認
